# Публичный мультиязычный контракт Xano

Этот каталог содержит следующий безопасный этап миграции. Файлы не изменяют production Xano автоматически: их нужно применить через Xano MCP или редактор после проверки реальных имён полей и резервной копии.

## Что теперь ожидает сайт

Публичные endpoints принимают необязательный `lang` со значением `de`, `ru`, `uk` или `en`. Старый вызов без `lang` продолжает работать и использует `ru` как язык совместимости. Для существующих записей миграция сначала определяет `source_locale`; технический fallback в resolver остаётся `ru`, пока поле не заполнено.

Каждое объявление сохраняет исходные поля без изменений и может вернуть вложенный объект `translation`:

```json
{
  "source_locale": "ru",
  "translation": {
    "id": 123,
    "locale": "de",
    "source_locale": "ru",
    "source_hash": "sha256 исходного содержимого",
    "status": "completed",
    "content": {
      "title": "Audi A4 schwarz",
      "description": "…",
      "seo_title": "…",
      "seo_description": "…",
      "image_alt_texts": [],
      "search_keywords": []
    }
  }
}
```

Сайт применяет только разрешённые текстовые поля и только когда статус равен `completed`, а язык перевода совпадает с запрошенным. При `missing`, `processing`, `failed`, `stale`, неизвестном языке или пустом тексте показывается оригинал продавца. Оригинальный заголовок и описание сохраняются в памяти страницы для разбора старых структурированных строк и никогда не записываются обратно.

## Обязательные ограничения Xano

- Не перезаписывать `car_listings.title`, `description` и SEO-поля переводом.
- Вычислять `source_hash` из всех переводимых исходных полей, а не только из описания.
- Помечать старые переводы `stale`, если хеш больше не совпадает.
- Возвращать только одну последнюю завершённую запись для пары `car_listing_id + lang + source_hash`.
- Не возвращать внутренние ошибки, prompt, токены, секреты, пользовательские контакты или записи других объявлений.
- Для `ru` при `source_locale=ru` не создавать бессмысленный перевод: возвращать `translation=null`.
- Сохранить прежнюю публичную фильтрацию статусов объявлений.

## Порядок активации

1. Сверить физические поля таблиц `locales`, `taxonomy_translations`, `car_listing_translations` и `translation_jobs` — выполнено 4 августа 2026 года.
2. Создать резервную копию затрагиваемых таблиц.
3. Активировать `GET /locales` и `GET /taxonomies` — выполнено 5 августа 2026 года; справочники пока пусты до отдельной миграции данных.
4. Добавить `lang` и resolver перевода сначала в тестовую копию `GET /cars/{slug}` — выполнено и опубликовано 5 августа 2026 года.
5. Проверить оригинал, готовый перевод, отсутствующий перевод и устаревший хеш.
6. Обновить список `/cars` batch-resolver'ом и проверить `de`, `ru`, `uk`, `en`, неизвестную локаль — выполнено и опубликовано 5 августа 2026 года.
7. Обновить `/seller-listings` и `/related`, сохранив batch-чтение и прежнюю публичную фильтрацию — выполнено и опубликовано 5 августа 2026 года.
8. Сформировать legacy dry-run и создать translation jobs небольшим повторяемым пакетом — выполнено для трёх публичных объявлений.
9. Следующий этап: реализовать canary-worker для одной задачи, проверить запись перевода и только затем продолжать очередь.

Первый legacy dry-run и `translation-batch-01` выполнены 5 августа 2026 года: восемь задач для трёх публичных объявлений находятся в `queued`. Следующий шаг — canary-worker для одной задачи; оставшиеся задачи нельзя массово запускать до проверки результата canary.

Машиночитаемая версия контракта находится в `public-contract.json`.
