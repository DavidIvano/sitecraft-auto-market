# SiteCraft API state contract

Статус: Stage 0 canonical contract  
Дата: 19 июля 2026 года

## Цель

Frontend, Xano и Cloudflare Worker должны одинаково различать вход, право доступа, выключенную функцию и временную ошибку. Нельзя использовать один `403` для всех состояний или удалять browser-сессию из-за временной ошибки конкретного endpoint.

## Канонические состояния

| `code` | HTTP | Значение | Действие frontend |
| --- | ---: | --- | --- |
| `SIGN_IN_REQUIRED` | 401 | Токен отсутствует или подтверждённо истёк | Показать вход и сохранить `next` |
| `ROLE_REQUIRED` | 403 | Пользователь вошёл, но роль не разрешена | Не удалять токен, открыть кабинет |
| `MODULE_DISABLED` | 503 | Функция выключена серверной настройкой | Не удалять токен, объяснить состояние |
| `RATE_LIMITED` | 429 | Превышен лимит | Не удалять токен, учитывать `Retry-After` |
| `TEMPORARILY_UNAVAILABLE` | 502/503/504 | Зависимость временно недоступна | Сохранить сессию, предложить повтор |
| `NOT_FOUND` | 404 | Запись отсутствует или недоступна текущему владельцу | Вернуться к списку |

## Ответ ошибки

```json
{
  "code": "ROLE_REQUIRED",
  "message": "Deal Finder role is required.",
  "request_id": "optional-server-request-id",
  "retry_after_seconds": null
}
```

`message` предназначен для журналов и не обязан показываться пользователю дословно. Пользовательский текст выбирается frontend по `code`.

## Правила авторизации

1. Все защищённые Xano endpoints используют `automarket_users` auth.
2. Роль и `user_id` загружаются из `$auth`, а не из body/query.
3. Deal Finder разрешает только `admin` и `deal_finder_admin`.
4. Каждая запись Deal Finder проверяется по `row.user_id == current_user.id`.
5. Frontend-проверка роли управляет навигацией, но не заменяет серверную проверку.
6. `401` от прикладного endpoint не очищает токен, пока `/auth/me` не подтвердит завершение сессии.
7. `/auth/me` повторяет единичный `401` один раз. Только второй последовательный `401` очищает локальную сессию.
8. `403`, `429` и `5xx` никогда не очищают токен.

## Правила совместимости

- На переходный период frontend принимает `code` и `error_code`.
- Endpoint без кода отображается по HTTP status.
- Новые endpoints обязаны возвращать канонический `code`.
- Xano должен добавлять `request_id` в журналы ошибок до Stage 1.

## Проверка готовности

- перезагрузка защищённой страницы не создаёт новый вход;
- кратковременный первый `401` не удаляет токен;
- подтверждённые два `401` переводят на вход;
- `403` показывает отсутствие роли без выхода;
- `503` сохраняет видимую сессию и даёт повторить;
- переход после входа возвращает пользователя на исходный URL.
