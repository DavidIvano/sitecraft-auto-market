# SiteCraft Auto Market — отчёт по производительности и изображениям

Дата аудита: 16 августа 2026 года  
Статус: код production-кандидата готов; повторный production Lighthouse обязателен после публикации Cloudflare Pages.

## 1. Результат этапа

Реализован единый безопасный конвейер изображений от браузера до R2:

1. Браузер исправляет EXIF-ориентацию, уменьшает фотографию и удаляет метаданные через повторное кодирование canvas.
2. Браузер последовательно снижает качество и размеры, пока WebP-мастер не станет не больше 150 KB и 1600×1600 px.
3. HEIC/HEIF с iPhone обрабатывается в браузере, если декодер доступен. Если браузер не умеет декодировать HEIC, только этот исходник передаётся защищённой Cloudflare Function для конвертации.
4. Сервер проверяет MIME, сигнатуру файла, реальные размеры, число пикселей и размер файла. Несовпадение MIME и magic bytes блокируется.
5. В R2 сохраняется только проверенный WebP-мастер. Исходный JPEG, PNG, AVIF или HEIC в R2 не сохраняется.
6. Частично записанные файлы удаляются при ошибке пакетной загрузки.
7. `thumb`, `card` и `detail` создаются по запросу через Cloudflare Images и кэшируются на год. Три физические копии в R2 не создаются.

Официальная база выбранного решения: [Cloudflare Images binding](https://developers.cloudflare.com/images/optimization/binding/), [Image Transformations](https://developers.cloudflare.com/images/optimization/transformations/overview/), [поддерживаемые форматы и лимиты](https://developers.cloudflare.com/images/get-started/limits/).

## 2. Параметры конвейера

| Уровень | Размер | Качество | Назначение |
|---|---:|---:|---|
| master | до 1600 px, до 150 KB | адаптивно 82% → 38% | единственный файл в R2 |
| thumb | 320 / 480 px | 60 / 68 | миниатюры галереи |
| card | 480 / 800 px | 68 / 72 | карточки каталога, главной и избранного |
| detail | 640 / 1280 / 1600 px | 68 / 72 / 78 | страница автомобиля и LCP |

Серверный fallback дополнительно уменьшает master шагами от 1600 px / 78 до 800 px / 50. Если ни один результат не укладывается в 150 KB, загрузка завершается понятной ошибкой и в R2 ничего лишнего не остаётся.

## 3. Что изменено в public frontend

- Все общие карточки используют `srcset`, `sizes`, фиксированные `width`/`height`, `loading` и `decoding`.
- Alt формируется из названия автомобиля, года и города; на detail используется SEO-alt конкретного фото.
- На главной LCP-фото выводится сервером в HTML с `loading="eager"` и `fetchpriority="high"`. Остальные изображения ленивые.
- В каталоге, на страницах бренда/модели и локализованных страницах высокий приоритет получает только первое потенциальное LCP-изображение.
- Миниатюры detail-галереи запрашивают 320/480 px, а не полноразмерный detail.
- Устаревший `/cars/detail?slug=...` больше не загружает весь автомобиль клиентским JavaScript: он делает постоянный redirect на канонический `/cars/{slug}/`.
- Удалён повторный browser-fetch списка `/cars` после SSR на главной и в каталоге.
- Удалён повторный browser-fetch detail только ради контактов продавца; публичные контакты приходят с SSR-данными объявления.
- Public и workspace получили раздельные CSS entrypoints. Общие токены, layout и controls загружаются один раз; catalog/public и dashboard/workspace подключаются только к своему shell.
- Для публичных locale-страниц сохранён Cloudflare CDN cache с `s-maxage` и `stale-while-revalidate`; персонализированные ответы остаются `private, no-store`.

## 4. Каталог и серверная пагинация

Во frontend подготовлен `getApprovedCarsPage()` с параметрами `page`, `limit` (максимум 24), `sort` и фильтрами. Он понимает серверный объект с `items`, `page`, `limit`, `total`, `total_pages` и временно поддерживает старый массив без изменения текущего поведения.

Точный контракт Xano находится в `docs/xano-public-catalog-pagination-contract.md`. До его реализации в Xano UI продолжает работать с текущим ответом, чтобы не ломать каталог. После появления подтверждённого endpoint нужно переключить каталог на 20–24 записи на страницу и удалить совместимый array-fallback.

## 6. Lighthouse до публикации

Проверены production и локальная production-сборка: главная, `/cars/` и реальная detail-страница; mobile и desktop.

### Текущий production baseline

| Страница | Режим | Perf | A11y | BP | SEO | LCP | CLS | TBT | Передано |
|---|---|---:|---:|---:|---:|---:|---:|---:|---:|
| `/` | desktop | 77 | 100 | 100 | 100 | 4,74 s | 0 | 0 ms | 7,46 MB |
| `/` | mobile | 67 | 100 | 100 | 100 | 24,76 s | 0 | 20 ms | 4,30 MB |
| `/cars/` | desktop | 78 | 96 | 100 | 100 | 4,29 s | 0,002 | 0 ms | 8,47 MB |
| `/cars/` | mobile | 68 | 98 | 100 | 100 | 25,86 s | 0 | 0 ms | 7,46 MB |
| detail | desktop | 91 | 100 | 100 | 100 | 1,98 s | 0,015 | 0 ms | 7,19 MB |
| detail | mobile | 72 | 100 | 100 | 100 | 8,26 s | 0,010 | 0 ms | 3,92 MB |

Вывод baseline: интерактивность и стабильность layout уже хорошие (`TBT` 0–20 ms, `CLS` 0–0,015), SEO равно 100. Главный дефект — 4–8 MB изображений и связанный с ними mobile LCP.

### Локальная production-сборка

Локальная сборка подтвердила SSR, responsive-разметку, отсутствие повторных Xano-запросов и, например, дала на главной desktop Performance 94 и LCP 1,65 s. Но эти числа нельзя считать финальным `after`: существующие URL фотографий ведут на production-домен R2 handler, где новый Cloudflare Images transform ещё не опубликован. Поэтому локальный прогон всё ещё скачивал 5–10 MB старых изображений и mobile LCP оставался нестабильным.

Честный итоговый `before → after` будет зафиксирован только после deployment. Преждевременно объявлять целевой LCP достигнутым нельзя.

## 8. Обязательный release-gate

Перед признанием этапа полностью завершённым:

1. Опубликовать текущий `main` в Cloudflare Pages.
2. Убедиться, что binding `IMAGES` доступен в production и preview, а Image Transformations активны в аккаунте.
3. Загрузить свежие JPEG и HEIC с iPhone. Проверить в R2: magic bytes `WEBP`, размер ≤ 153 600 B, максимальная сторона ≤ 1600 px.
4. Проверить ответы `?width=480`, `?width=800`, `?width=1600`: корректные размеры, WebP, годовой immutable cache, заметно меньший `Content-Length`.
5. Повторить Lighthouse по той же матрице и записать production `after`. Gate проходит только при LCP ≤ 2,5 s, CLS ≤ 0,1, INP ≤ 200 ms и отсутствии функциональных регрессий.
6. Реализовать и подтвердить Xano pagination contract, после чего включить 20–24 объявления на страницу.

Если `IMAGES` binding не активен, загрузка JPEG/HEIC/PNG fail-closed с `IMAGE_OPTIMIZER_MISSING`; сервер не сохранит тяжёлый или непроверенный оригинал. Уже оптимизированный валидный WebP до 150 KB продолжит загружаться безопасно.

## 9. Оставшийся технический долг

- `global.css` остаётся крупным legacy-слоем внутри shared entry. Route CSS уже разделён и проходит бюджет, но следующий безопасный CSS-этап — постепенно переносить оставшиеся общие селекторы в модульные public/workspace файлы без визуального переписывания сайта.
- Крупнейший JS chunk (таблицы taxonomy/i18n) проходит бюджет с небольшим запасом. После языковых релизов его следует разделить по locale и загружать только выбранный словарь.
- Seller/related блоки detail пока вычисляются сервером параллельно. Это сохраняет SEO-ссылки и стабильный интерфейс; переносить их в deferred API можно только после измерения TTFB и без потери crawlability.
